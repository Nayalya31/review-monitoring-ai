# ИИ-мониторинг и анализ отзывов

Python worker и Flask-модуль для приёма, анализа и модерации отзывов. Проект развивает учебный обработчик; автоматически публиковать ответы запрещено.

## Возможности

- Форма с CSRF, honeypot, проверкой длины, отдельными согласиями и ограничением частоты.
- Отдельная SQLite WAL: отзывы, структурированный анализ, черновики, журнал уведомлений и действий администратора.
- OpenAI Responses API: тональность, уверенность, суть, причины недовольства, рекомендуемое действие и проект ответа.
- Ограниченные повторы, таймауты, суточный лимит обращений и максимальная длина ответа.
- Telegram по негативным отзывам; остальные сохраняются в истории. Уведомления настраиваются через окружение.
- Ручное разрешение публикации отзыва и отдельное утверждение ответа через существующий вход Flask-Login.
- Docker с непривилегированным пользователем, ограничением ресурсов, read-only root и healthcheck.

## Быстрый запуск

Python 3.12+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python scripts/create_env.py
.venv/bin/python -m pytest -q
.venv/bin/python worker.py
```

`create_env.py` создаёт локальный .env с сильным токеном и правами 0600, не перезаписывая существующие настройки. Значения ключей заполняются локально, не через Git. Все параметры перечислены в `.env.example`.

Для веб-интерфейса подключите пакет к своему Flask-приложению и вызовите `init_reviews(app)` после регистрации маршрутов и Flask-Login/Flask-WTF. Сохраните существующие проверки CSRF. Передайте `REVIEWS_DATABASE_PATH` — отдельный файл БД. Сайт и worker должны видеть один физический файл на локальном диске одного хоста. Шаблоны наследуют `base.html` и ожидают маршруты `contact`, `admin_requests`, `cases`; их нужно адаптировать к своему сайту. Патч конкретного production-сайта в публичный репозиторий не входит.

Worker читает очередь из базы напрямую. `client.py` — дополнительный защищённый HTTP-адаптер чтения. Проект принимает отзывы собственного сайта; сторонние площадки не парсит.

## Поток данных

Форма → отдельная база → worker → разрешённый ИИ-анализ либо локальная оценка с ручной проверкой → анализ и черновик → очередь Telegram → решение администратора.

Приём реальных отзывов выключен по умолчанию. Перед запуском необходимо утвердить условия обработки данных, регион хранения и резервных копий, сроки хранения и порядок удаления. Наличие кода не является юридическим заключением о соответствии 152-ФЗ.

Внешний ИИ не получает исходный текст реального посетителя. Требуются флаг `EXTERNAL_PROCESSING_AUTHORIZED` и проверенный администратором обезличенный текст. Для тестов есть фиксированный синтетический DEMO-каталог. Регулярные выражения для удаления контактов не гарантируют обезличивание.

Telegram по умолчанию получает только ID и ссылку в защищённую панель. Кнопка «Открыть отзыв» ведёт в веб-панель; подтверждение и доработка выполняются после входа администратора. Telegram webhook/polling не подключается, чтобы не мешать другим обработчикам бота.

## Основные параметры

| Переменная | Назначение |
|---|---|
| ENVIRONMENT | production включает проверки HTTPS и стойкости токена |
| TARGET_SITE_URL | Адрес собственного сайта |
| WORKER_API_TOKEN | Защищает чтение служебного API, передаётся только заголовком |
| DATABASE_PATH / REVIEWS_DATABASE_PATH | Пути worker и сайта к отдельной базе |
| OPENAI_API_KEY / OPENAI_MODEL | Ключ и настраиваемая модель |
| LLM_DAILY_REQUESTS / LLM_MAX_OUTPUT_TOKENS | Ограничения запросов и ответа |
| TELEGRAM_BOT_TOKEN / TELEGRAM_USER_CHAT_ID | Получатель уведомлений; старый TELEGRAM_CHAT_ID поддерживается |
| NOTIFY_NON_NEGATIVE | Уведомлять также о положительных и нейтральных отзывах |
| EXTERNAL_PROCESSING_AUTHORIZED | Разрешение внешней обработки после проверки оснований |
| TELEGRAM_INCLUDE_TEXT | Включить проверенный обезличенный текст в сообщение |
| REVIEWS_INTAKE_ENABLED | Включить форму после утверждения условий |
| PRIVACY_POLICY_URL / CONSENT_VERSION | Утверждённые условия и версия согласия |
| REVIEWS_TRUSTED_PROXY_IPS | Только проверенные адреса собственных доверенных прокси |

Лимит запросов не равен точному денежному бюджету: дополнительно настройте лимит у провайдера.

## Развёртывание

Создайте отдельный защищённый каталог данных. Укажите его в REVIEWS_DATA_DIR и согласуйте права пользователя сайта и контейнера через REVIEWS_UID/REVIEWS_GID. Секреты держите в отдельном файле, путь к нему задайте REVIEWS_ENV_FILE. Публикуйте сайт через HTTPS; сам worker сетевых портов не открывает.

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 worker
docker compose stop worker
```

Перед обновлением сохраните код, конфигурацию и согласованную резервную копию данных. Обновляйте только этот сервис. Не используйте `down -v` для рабочих данных. Для резервного копирования:

```sh
python3 scripts/backup.py /path/to/reviews.sqlite3 /private-backups/reviews-date.sqlite3
```

Используется SQLite backup API. Для восстановления остановите процессы, сохраните текущий каталог отдельно, восстановите проверенную копию в новый каталог и выставьте права. Не смешивайте старые WAL/SHM с восстановленной базой. Старый backup может откатить журнал уведомлений: сверяйте доставку перед повторной обработкой.

## Проверки и ограничения

25 автоматических тестов проверяют тональности, повторы, перезапуск, конкуренцию, ошибки LLM/Telegram, токены, права модерации, CSRF, HTML, изоляцию prompt injection и privacy gate. Внешние API в автотестах подменены. Отдельный `scripts/live_smoke.py` выполняет платные DEMO-запросы и отправляет тест в настроенный Telegram; запускайте его намеренно.

Три синтетических отзыва прошли реальный OpenAI, негативный тест доставлен в Telegram. Docker проверен на Python 3.12 и linux/amd64. DEMO развёрнуто и проверено: [кейс на сайте](https://24tali-ai.ru/review-monitoring-assistant). Синтетический отзыв прошёл через HTTPS-админку, ИИ, сохранение и Telegram. Перезапуск worker не создал дублей. Приём реальных отзывов выключен до утверждения условий обработки данных.

После неизвестного исхода Telegram-запроса запись получает `uncertain`, автоматический повтор не выполняется. Требуется сверка администратором. После сбоя между LLM-ответом и записью в БД возможен повторный платный вызов. Абсолютная гарантия exactly-once для внешних API не заявляется.

SQLite рассчитан на один хост и локальный диск. Для нескольких серверов потребуется отдельный PostgreSQL и миграция.
